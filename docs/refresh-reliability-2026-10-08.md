# WAMO 갱신 복구 및 52주 기준 전환

2026-10-08 사용자 요청: 반복 갱신 실패를 해결하고, 역사적 신고가 대신 52주 신고가로 선별한다.

## 확인한 장애

- 실행 37711079999에서 미국 877개 중 876개가 전 거래일 캐시, 1개만 최신 가격으로 수집되어 게시가 차단됐다.
- 기존 미국 가격 경로는 Yahoo query1/query2뿐이었다. 같은 공급자의 서버 전환만으로는 공급자 장애를 복구할 수 없었다.
- 글로벌 발견 탭은 원본 보고서의 UPSTREAM_NOT_READY에 종속되어 있었다.

## 변경

- 미국 일봉: Yahoo → Nasdaq 일별 이력 → NAVER 해외주식 차트. 날짜, 종목, 유한 수치, 가격 범위, 거래량, 중복 날짜와 응답 누락을 확인한다.
- 공급자별 연속 장애 시 60초간 요청을 줄이고 이후 재확인한다. 장애가 종목 900개로 전파되어 같은 요청이 반복되는 것을 제한한다.
- 모든 가격 제공처는 최근 약 3년만 수집한다. 52주 선별은 252거래일 이력이 있는 종목만, 고점 대비 7% 이내를 사용한다. 200일선과 기존 3년 추세 지표를 위한 이력은 유지한다.
- 서로 다른 수정주가 체계의 이력을 이어붙이지 않는다. 종목마다 제공처와 가격 조정 방식을 기록한다. 역사적 신고가는 계산하지 않는다.
- 가격 최신성 검사를 보조 재무 수집보다 먼저 실행한다. 전체 가격 갱신이 불가능하면 기존 정상 화면과 실제 기준일을 보존한다.
- 외부 레이더 원본이 준비되지 않으면, 검증된 WAMO 가격에서 한국·미국의 실제 장중/종가 52주 신고가를 계산한다. 원본 미연결 시 일본·중국·홍콩은 이 대체 범위에 포함되지 않는다.
- 종목별 가격 이력 검증 실패는 해당 종목을 제외하고 건수를 표시한다. 전체 종목의 90% 이상이 최신 가격·이력 검증을 통과해야 대체 신고가 목록을 게시한다. 한국 가격도 잘못된 OHLCV를 받으면 다음 공급자를 사용한다.
- Google Finance HTML은 종가 교차확인용으로만 구현했다. 날짜의 연도가 명확하지 않은 응답을 일봉 대체 자료로 사용하지 않는다. Stooq는 브라우저 검증 응답이 반환되어 자동 경로에 넣지 않았다.

## 운영 확인

`python -m unittest discover -s tests -v`

`node --test tests/status.test.mjs tests/discovery.test.mjs`

`python tests/browser_smoke.py` 및 `python tests/discovery_browser.py`

주요 로그: 가격 경로별 attempts/successes/failures/skipped, 검증된 거래일, 종목 수. 오래된 HTTP 200 응답도 성공이 아닌 다른 제공처로의 전환 사유다.

공급자 전체 장애나 예약 실행 서비스 지연을 완전히 없앨 수는 없다. 실패 표시를 숨기거나 오래된 가격의 날짜만 바꿔 성공으로 표시하지 않는다.
