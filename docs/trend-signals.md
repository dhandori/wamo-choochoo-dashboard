# 추세 신호 · 지금 갱신 · 텔레그램 알림

## 무엇을 하나요

`wamo_trend.py`가 이미 검증된 가격 화면(index.html / us.html)의 일봉 이력으로 아래를 계산해 `wamo_trend.json`에 저장합니다. 레이더 화면의 **추세 신호** 탭과 맨 위 **시장 날씨** 띠가 이 파일만 읽습니다.

| 항목 | 계산 방법 |
|---|---|
| 시장 날씨 | 아래 5개를 좋음(+1)·보통(0)·나쁨(−1)으로 합산. +2 이상 공격 가능, −2 이하 현금 비중 확대 |
| ① 지수 추세 | 미국 S&P 500 + 나스닥, 한국 KOSPI + KOSDAQ. 둘 다 50·200일선 위면 좋음, 하나라도 200일선 아래면 나쁨, 그 사이(50일선 아래·200일선 위)는 보통 |
| ② 이평선 기울기 | 50일선은 10거래일 변화율(±0.5% 안이면 평평), 200일선은 20거래일 변화율(±0.3%). 두 지수 모두 50·200일선 상승이면 좋음, 200일선 하락(또는 50일선 하락 + 200일선 평평)인 지수가 있으면 나쁨 |
| ③ 분산일 | 지수가 0.2% 이상 하락 + 거래량이 전날보다 많은 날, 최근 25거래일. 이후 그날 종가보다 5% 넘게 오르면 제외. 두 지수 중 많은 쪽 기준: 3번 이하 좋음, 6번 이상 나쁨 |
| ④ 시장 체력 | 50일선 위 종목 비율 60% 이상 좋음, 40% 미만 나쁨 |
| ⑤ 신고가 vs 신저가 | 신고가가 신저가의 2배 이상이고 전체의 2% 이상이면 좋음, 신저가가 더 많거나 5% 이상이면 나쁨 |
| RS선 신고가 | RS선 = 종가 ÷ 지수. 최근 252거래일 최고치. 주가가 고점에서 3% 넘게 아래면 "주가보다 먼저" |
| 팔 때 경고 | 최근 20거래일 안에 Stage 2였거나 신고가 근처였던 종목만. 50일선 대량 이탈(1.4배 거래량), Stage 3·4, RS 5일 20점 급락, 정배열 붕괴, 대량 급락 |
| 천장 신호 | `wamo_climax.py`. **일중전환·천장형**: 장중 50거래일 최고가 갱신 + 전날보다 낮은 종가 + 그날 범위 아래쪽 절반 마감 + 하루 범위가 20일 평균 이상(종목은 전날 50일선 위). **바닥형**: 장중 20거래일 최저가 이탈 + 전날보다 높은 종가 + 위쪽 40% 마감(종목은 200일선 위). **클라이맥스 런**: 상승 정렬에서 15거래일 안 최저 종가 대비 종목 25%·지수 12% 이상 + 징후(최대 하루·5일 상승, 10일 중 7일 상승, 소진 갭, 50·200일선 과이격, 최대 거래량) 종목 2개·지수 3개 이상. **천장 경고**: 클라이맥스 뒤 10거래일 안 천장형 반전. 지수는 지난 1년 기록과 5·20일 뒤 변화를 함께 보여 줌 |
| 실적발표 | 미국만. Nasdaq 공개 실적 일정, 12시간에 한 번만 조회해 `wamo_earnings_cache.json`에 저장 |
| 신호 성적표 | 천장형 일중전환·천장 경고도 매도 신호로 기록(새 신호는 처음 한 번 최근 40거래일 역산). 신호가 난 날 종가 기준 5·20·60거래일 뒤 수익률과 지수 대비 초과수익. `wamo_signal_log.json`에 누적. 첫 실행 때 최근 40거래일을 현재 종목 목록으로 역산(생존 편향 있음) |

차트: 종목 상세에서 종가·20/50/150/200일선·거래량(50일 평균선)·가로축(날짜)·세로축(가격)·마우스 표시, 그 아래 RS선 차트. 목록에는 60거래일 미니 차트(종가·50·200일선). 차트 자료는 `wamo_chart_KR.json`, `wamo_chart_US.json`(종목별 260거래일 종가, 120거래일 거래량)이며 차트를 처음 열 때만 내려받습니다. 저장 이력이 260거래일이라 6개월 보기에서 200일선은 최근 61거래일만 그려집니다.

외부 호출은 지수 이력(Yahoo, 시장별 주지수·보조지수 각 1회)과 Nasdaq 실적 일정뿐입니다. TradingView는 사용하지 않습니다. 지수 자료가 실패하면 스크리닝 종목의 동일가중 중앙값 지수로 대신 계산하고 분산일은 표시하지 않습니다.

생성 시점: 시장별 가격 갱신 성공 직후, 그리고 갱신 대상이 없을 때에도 추세 파일이 가격 화면보다 뒤처져 있으면 따라잡습니다. 실패해도 가격 게시는 막지 않습니다.

## 지금 갱신 버튼

레이더 상단의 **지금 갱신**은 실행 상태 파일(`wamo_refresh_status.json`)을 보고 다음일 때 켜집니다: 실패, 40분 넘게 멈춤, 예약 시각 90분 경과, 일부 종목 누락, 지난 거래일 데이터.

누르면 안내 창 → GitHub Actions의 `WAMO 자동갱신` 실행 화면이 열리고, `Run workflow`를 누르면 됩니다(수동 실행은 이제 기본으로 게시까지 합니다). 화면은 GitHub 공개 API(ETag 사용)와 상태 파일로 실행 대기 → 수집 중 → 완료/실패를 보여주고, 완료되면 새 데이터를 다시 읽습니다. 진행 중에는 버튼이 잠겨 중복 요청을 막고, 워크플로의 concurrency 대기열도 실제 중복 실행을 막습니다.

### 누락 종목 재수집

예전에는 한 거래일이 "성공"으로 기록되면 일부 종목이 빠져도 다시 수집하지 않았습니다. 이제 `wamo_refresh_state.json`에 `missingCount`를 기록하고(예전 파일은 상태 파일의 신규수집 수로 계산):

- 수동 실행: 누락이 있으면 그 시장을 다시 수집
- 자동 복구 실행: 2시간 간격, 거래일당 최대 2회
- 재수집 결과가 더 나쁘거나 실패하면 이전 검증 데이터를 그대로 유지

## 텔레그램 알림 켜기 (무료)

1. 텔레그램에서 `@BotFather` → `/newbot`으로 봇을 만들고 토큰을 받습니다.
2. 만든 봇에게 아무 메시지나 보낸 뒤 `https://api.telegram.org/bot<토큰>/getUpdates`에서 `chat.id`를 확인합니다.
3. GitHub 저장소 → Settings → Secrets and variables → Actions에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`를 추가합니다.
4. 따로 챙길 종목은 `wamo_watchlist.json`에 넣습니다.

시장별로 거래일마다 한 번만 보냅니다(`wamo_alert_state.json`). 비밀값이 없으면 아무것도 보내지 않습니다.
