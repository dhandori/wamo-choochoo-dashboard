# WAMO 갱신 복구 설계

사용자 요청: 전체 효율화와 갱신 중단 방지, 개선 방식은 위임. 기존 GitHub Pages·종목 기준·검증 규칙 유지. 중단 자체의 절대적 보장은 하지 않으며, 지연과 오류를 보이게 하고 다음 실행에서 복구한다.

확인: 기본 runner는 실패한 세션 자동 재시도를 차단한다. 예약은 시장당 한두 번으로 실행 누락을 따라잡지 못한다. 레이더 원본은 waiting_data이며 이를 우회해 공개하면 안 된다. 카탈로그와 레이더가 시각만 바꿔 반복 커밋한다. 브라우저는 상태를 처음 한 번만 읽는다.

변경: 2시간 간격 복구 확인, 완료 세션 중복수집 금지, 실패 후 30/60/120/240/360분 대기 후 재시도, 시작 체크포인트와 중단 정리, 시장별 실패 격리. 실제 데이터가 바뀔 때만 카탈로그 저장. 레이더 오류 종류를 안전한 코드로 구분하고 동일 결과 재배포 제한. 상태 UI는 1분 간격·탭 복귀 시 재확인, 10초 네트워크 제한, 오래된 페이지에는 새로고침 안내. 과거 가격이나 검증 전 신고가를 최신으로 표시하지 않는다.

외부 한계: GitHub cron 지연과 원본 데이터 부족은 별도 운영 상태이며 코드가 없던 가격을 만들어낼 수 없다. 원본 레이더의 별도 저장소는 읽기 조사만 수행하고 대상 저장소에서 검증 기준을 낮추지 않는다.
